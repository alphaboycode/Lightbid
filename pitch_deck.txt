2. THE PROBLEM: LEGACY WEB3 AUCTIONS ARE BROKEN
--------------------------------------------------------------------------------
The $40B+ digital collectibles, gaming assets, and tokenized real-world assets (RWA)
market relies heavily on auction-based price discovery. However, existing on-chain
auctions are plagued by fatal architectural flaws:

* Last-Second Bot Sniping (MEV / Gas Wars):
  On conventional platforms, auctions have rigid ending blocks. Automated sniper
  bots monitor the mempool and submit winning bids in the final fraction of a second
  with inflated priority gas fees. Legitimate human bidders are completely boxed out,
  destroying fair price discovery and depressing seller revenues.

* Push-Payment Denial of Service (DoS):
  Standard auction contracts attempt to "push" refunded funds back to the previous
  highest bidder inside the `bid()` transaction. If a malicious bidder participates
  via a smart contract with a reverting `receive()` or fallback function, all subsequent
  bids will fail, locking the malicious bidder as the perpetual winner at a bargain price.

* Excessive Wrapping & Friction:
  Platforms on other chains force users to wrap native assets into WETH or synthetic
  escrow tokens, adding unnecessary approval transactions, high gas costs, and
  cognitive barriers for mainstream users.

* Centralized & Fragile Metadata:
  Many marketplaces rely on centralized Web2 servers or transient API gateways for
  NFT metadata, resulting in broken image links, 404 errors, and disappearing media.


3. THE SOLUTION: LIGHTBID PROTOCOL
--------------------------------------------------------------------------------
Lightbid reimagines decentralized auctions with mathematical fairness, absolute
security, and frictionless user experience:

* Dynamic Anti-Snipe Clock Extension:
  When an auction enters its final 10-minute window (`EXTENSION_WINDOW = 10 minutes`),
  any new valid outbid resets the remaining time by adding 10 minutes
  (`EXTENSION_DURATION = 10 minutes`). This continues until true market equilibrium
  is reached, guaranteeing that every bidder has sufficient time to respond.

* Pull-Payment Escrow Ledger:
  Instead of pushing funds to previous bidders, Lightbid credits outbid amounts to
  an internal mapping (`pendingReturns[bidder] += previousBid`). Bidders can claim
  all accumulated refunds across multiple auctions in a single, safe transaction
  via `withdrawPendingReturns()`. Even if an outbid address reverts or fails, the
  auction proceeds uninterrupted.

* Native BOT Settlement:
  All bids and settlements execute in Botchain's native `BOT` cryptocurrency.
  Zero token wrapping. Zero intermediate token approvals for bidders.

* Multi-Standard Asset Protocol:
  - ERC-721: Single 1-of-1 digital art and collectibles with safeTransferFrom.
  - ERC-1155: Batch tokens, semi-fungible tickets, and multi-edition game items.
  - ERC-20: Bundled fungible token auctions with optional admin allowlisting.

* Integrated Pinata IPFS Creator Studio:
  Creators can mint NFTs directly from the web interface, pinning both high-resolution
  media files and ERC-721 metadata JSON to Pinata Cloud IPFS in one unified workflow.


4. TECHNICAL ARCHITECTURE & PROTOCOL DESIGN
--------------------------------------------------------------------------------
Built with Solidity ^0.8.24, Foundry, and OpenZeppelin Contracts v5:

```
[ Create Auction ]
  ├── Transfers Asset to Lightbid Escrow (ERC-721 / 1155 / 20)
  ├── Enforces Duration Boundaries (15 minutes <= duration <= 30 days)
  └── Validates Min Bid Increment (1% to 50% / 100 to 5000 BPS)
         │
         ▼
[ Place Bid (Native BOT) ]
  ├── Checks msg.value >= reservePrice (first bid)
  ├── Checks msg.value >= highestBid + minIncrement
  ├── Dynamic Anti-Snipe Check:
  │     if (endTime - block.timestamp <= EXTENSION_WINDOW) {
  │         endTime += EXTENSION_DURATION;
  │         emit AuctionExtended(auctionId, endTime);
  │     }
  └── Safe Escrow Credit:
        pendingReturns[previousBidder] += previousBid;
         │
         ▼
[ Settle Auction ]                               [ Withdraw Escrow ]
  ├── Requires block.timestamp >= endTime          ├── Called by bidder at any time
  ├── Calculates Protocol Fee (default 2.5%)       ├── Checks-Effects-Interactions
  ├── Transfers Fee -> feeRecipient                ├── pendingReturns[bidder] = 0
  ├── Transfers Net Proceeds -> Seller             └── (bool sent, ) = bidder.call{value}
  └── Transfers Escrowed Asset -> Highest Bidder
```

Security Patterns & Invariants:
* ReentrancyGuard: Applied to all state-mutating functions.
* Checks-Effects-Interactions (CEI): State updated before external calls.
* Ownable2Step: Secure 2-step ownership transfer prevents protocol hijacking.
* Pausable: Emergency circuit breaker to halt new auctions/bids during upgrades.
* Math Safety: Capped protocol fee (`MAX_FEE_BPS = 1000` / 10%), bounded duration,
  and strict minimum increment enforcement.
